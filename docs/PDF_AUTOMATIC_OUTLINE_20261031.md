状态：93 正式签名压缩包已交付并保留数据安装到手机；自动导入专项和整组原生回归在模拟器通过。手机目录详细交互与人工速度验收 pending。

用户要求新增 PDF 的目录直接可用，或默认静默导入，减少等待和重复确认。本轮针对 PDF 内置章节目录，不增加文件夹扫描功能。

## 原因与实现

旧流程在正文发布后固定等待 400 ms，再从 InputStream 加载整份 PDF；即使文件已在本地，也会再次复制到 PDFBox 临时存储。页码索引逐一 getPage(i)，反复从页树根部查找。章节范围推导对每个节点重新排序及查找兄弟节点。解析完成后仍只弹确认框，未真正写入目录。

- 保留正文优先，在完整底图发布后立即启动后台目录读取，移除固定等待。
- 本地 file URI 使用现有 PDFBox 文件直读；外部 content URI 保留流读取，读取器及文件资源始终关闭。
- 页码索引改为页树顺序迭代，章节范围的兄弟排序和相邻关系只建立一次，保留原有父级边界规则。
- 首次打开自动使用现有事务 MERGE，保留手工节点，按 importKey 去重，存储完成立即刷新同一 Ready.outlineNodes。不弹导入确认或成功提示。
- 目录页读取期间显示“正在读取目录…”，禁止重复发起扫描；扫描入口采用同一互斥锁。失败仍明确反馈，协程取消正常传播。
- 明确点击“导入 PDF 目录”时仍可使用既有合并 / 替换操作；自动路径不会替换手工目录。已存储内置目录的重开沿用快速跳过解析路径。

## 开源对照

按用户要求先检索官方维护中的项目及许可证，再使用现有依赖实现：

| 项目 | 许可证与依赖 | 借鉴与限制 |
|---|---|---|
| [Mozilla PDF.js](https://github.com/mozilla/pdf.js/blob/master/web/app.js) | Apache-2.0；JavaScript / worker，与当前原生渲染器不同 | onePageRendered 后异步获取 outline 并直接更新目录；借鉴后台直达目录的交互，不引入 Web 渲染器或复制实现。 |
| [Apache PDFBox](https://github.com/apache/pdfbox) | Apache-2.0；Java。当前项目已有 Android 2.0.27 移植依赖 | 官方 [PDDocument 2.0](https://github.com/apache/pdfbox/blob/2.0/pdfbox/src/main/java/org/apache/pdfbox/pdmodel/PDDocument.java) 提醒批量 getPage 对大文档慢，应使用 getPages；文件加载可直接随机读取。复用既有 Android API，未升级依赖。 |

已知边界：外部流仍需临时存储；没有内置书签的扫描书不会凭空生成目录；少数坏目的页沿用既有近似及失败策略。无固定耗时或提速倍数承诺。
