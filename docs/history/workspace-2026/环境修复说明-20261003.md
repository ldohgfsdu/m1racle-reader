## 根因与证据

JDK 17 当前 Windows 默认 native.encoding 为 GBK。迁移后 GRADLE_USER_HOME 含中文，Gradle 生成的 UTF-8 worker 参数文件不能正确被 Java 启动器解释，导致 GradleWorkerMain 找不到。原 worker JAR 实际包含该类；同一 JAR 直接 `-cp` 可加载。设置 `-Dfile.encoding=UTF-8` 未解决参数文件中的路径解码。

将 Gradle 用户目录改为工作区英文联接后，UTF-8 参数文件中的 worker 路径能够加载到主类（无输入时抛 EOFException，证明已进入 main）；完整单测用于最终验证。没有更换 JDK、Gradle 或依赖版本，也未削弱测试。

## 使用

```powershell
# 单测 + Release Lint
./reader-build-local.ps1
# 使用本机已有缓存离线验证
./reader-build-local.ps1 --offline
# 单测 + Lint + 正式签名 Release
./reader-build-local.ps1 -Release --offline
# 当前终端手动开发
. ./reader-env-local.ps1
cd reader
./gradlew.bat --version
```

签名仍由 `signing/` 中的既有正式 p12 和口令文件提供，不长期设置密码环境变量，也不把口令写入命令或日志。JDK/SDK/Gradle 缓存仍实际位于 `D:/04_构建环境`，换机须重建目录联接。
