## 0. 产品定位

### 一句话定义

一款面向 Android 的轻量、本地优先、高颜值的**本地文档阅读器**，用来快速导入、管理和阅读 `.md / .markdown / .txt` 与 `.pdf` 文档。

### 产品关键词

**本地优先、启动快、阅读舒服、排版漂亮、无账号、无广告、无联网依赖。**

### 核心目标

用户打开 App 后，只需要完成三件事：

1. 导入或从系统「打开方式」进入一个 Markdown / PDF 文档；
2. 在主页看到最近阅读记录；
3. 进入阅读页，获得稳定、清爽、可跳转目录的阅读体验。

### 不做什么

当前阶段明确不做：

- 不做 Markdown 编辑器；
- 不做云同步；
- 不做账号系统；
- 不做社区、分享、评论；
- 不做复杂文件夹管理；
- 不做插件系统；
- 不做 AI 总结；
- 不做富文本笔记软件；
- 不做文档正文全文索引；已交付的跨文档本地搜索仅覆盖文档标题、高亮摘录与笔记；
- 不申请网络权限。

本项目第一阶段只解决一个问题：**让用户在 Android 手机上优雅地阅读本地 Markdown 文档。**

# 1. 项目概述与目标

## 1.1 背景痛点

当前手机端 Markdown 阅读体验常见问题：

- 大文件打开慢，长文滑动卡顿；
- 排版粗糙，标题、代码块、引用块层级不清晰；
- 很多工具偏“编辑器”，阅读体验不够沉浸；
- 部分工具强依赖账号、云同步或联网，用户缺乏安全感；
- Android 端缺少一个像 Notion 一样干净、但像 Obsidian 一样本地可信的 Markdown 阅读器。

## 1.2 目标用户

### 核心用户

- 程序员：阅读技术文档、README、笔记、API 说明；
- 学习型用户：阅读课程笔记、复习资料、长文档；
- Obsidian / Typora / Logseq 用户：希望在手机端快速查看本地 Markdown；
- 独立开发者 / 写作者：随时查看项目文档、草稿、PRD、知识库内容。

### 用户特征

- 对纯净体验敏感；
- 讨厌广告、账号和强制云同步；
- 能接受基础文件选择器导入；
- 更在意“读得舒服”和“稳定可靠”，而不是功能堆叠。

# 2. 产品原则

## 2.1 产品原则

不追求“大而全”，只追求：

- 打得开；
- 读得顺；
- 排版美；
- 能回到上次阅读位置；
- 能通过目录快速跳转；
- 完全本地、安全可信。

## 2.2 体验原则

### 阅读优先

阅读页是核心，不要让按钮、卡片、菜单抢内容的注意力。

### 本地优先

当前版本不申请网络权限，不上传文件，不读取用户无关目录。

### 少即是多

主页只做最近阅读，不做复杂文件管理器。

### 长文友好

对 10 万字以上 Markdown 文档，至少保证首屏快速出现，后续内容渐进解析或分块渲染。

# 4. 页面结构与交互流程

## 4.1 页面总览

当前共三个核心页面：

1. 主页：最近阅读列表；
2. Markdown 阅读页：Markdown 内容阅读 + 目录大纲 + 文档内搜索；
3. PDF 阅读页（viewer/pdf）：连续 / 单页 PDF 阅读 + 教材大纲 + 缩略图 + 章节导出。

阅读设置不设独立页面，为阅读页内底部面板（字号 / 行高 / 边距）。

---

## 4.2 Page 1：主页 Home

### 页面目标

让用户快速打开最近读过的文档，或者导入新的 Markdown 文件。

### 页面结构

#### 固定顶部区域

- 品牌标题、搜索、导入按钮固定在状态栏下方；导入中禁用重复操作并显示状态。
- 列表只在顶栏与底部导航之间滚动，不能覆盖状态栏、底栏或系统手势区域。

#### 阅读内容

- 最近打开的文档以“继续阅读”卡片展示，突出书名，阅读位置使用次要字号。
- 最近列表使用较轻的两行书名与小号进度；PDF 类型由图标表达，显示标题省略 `.pdf` 后缀，文件信息保留完整原名。
- 继续阅读和普通条目共用三点操作：文件信息、从文库移除。菜单锚定操作按钮，由平台处理空间不足时的位置。
- 文件信息可独立查看并复制完整文件名，展示格式和已知文件大小；不触发打开或移除。
- 空库显示导入引导，固定导入按钮仍可用。

### 主页交互

| 用户操作 | 系统反馈 |
|---|---|
| 点击导入 | 打开系统文件选择器 |
| 选择文件 | 显示导入状态并禁止重复提交；成功后进入阅读页，超限或读取失败时明确提示 |
| 点击继续阅读或列表条目 | 打开对应文件并恢复阅读位置 |
| 点击三点或长按条目 | 展开同一操作菜单 |
| 点击文件信息 | 查看/复制完整文件名，关闭后返回列表 |
| 点击从文库移除 | 确认框说明清除范围；确认后移除文档及关联阅读进度、书签、收藏、批注和应用内副本，不删除用户源文件；失败时恢复条目并提示 |
| 文件不存在 | 提示“文件可能已被移动或删除”，允许移除记录 |

## 4.3 Page 2：阅读页 Viewer

### 页面目标

提供沉浸、稳定、排版舒服的 Markdown 阅读体验。

### 页面结构

#### 顶部栏

- 返回按钮；
- 当前文件名；
- 目录按钮；
- 更多按钮。

顶部栏默认显示，向下阅读时可轻微隐藏或压缩，向上滑动时恢复。

#### 主体区域

Markdown 渲染内容：

- 标题有明确层级；
- 段落行距舒适；
- 列表缩进清晰；
- 引用块有左侧竖线；
- 代码块使用等宽字体和独立背景；
- 链接可点击，但不主动联网预览；
- 长文滑动不卡顿。

#### 目录抽屉 TOC

从左侧或右侧弹出均可，建议右侧抽屉，避免和 Android 返回手势冲突。

目录内容：

- 自动提取 H1、H2、H3；
- H2 / H3 使用缩进表达层级；
- 当前阅读位置对应标题高亮；
- 点击目录项后跳转到对应标题位置；
- 点击抽屉外区域关闭。

### 阅读页交互

| 用户操作 | 系统反馈 |
|---|---|
| 点击返回 | 回到主页，并保存阅读位置 |
| 点击目录按钮 | 打开目录抽屉 |
| 点击目录项 | 跳转到对应标题 |
| 滑动正文 | 正常滚动，自动更新阅读进度 |
| 退出页面 | 保存最后阅读位置 |
| 点击链接 | 弹出确认后用系统浏览器打开 |
| 点击代码块 | 可选：展开横向滚动或复制代码 |

# 5. 视觉风格定义

## 5.1 视觉方向

整体风格采用：

**Notion 式极简排版 + Obsidian 式本地文档气质 + Android Material 3 组件体系。**

不要做成重型知识库，也不要做成花哨阅读 App。

目标感觉：

- 安静；
- 干净；
- 专注；
- 有纸张感；
- 有高级文档感；
- 适合长时间阅读。

## 5.2 色彩

### 浅色模式

- 背景：暖白 / 米白；
- 正文：接近黑色但不死黑；
- 次级文字：灰褐色；
- 强调色：墨绿、陶土色或跟随 Dynamic Color；
- 卡片：轻微色差，不要重描边。

### 深色模式

- 背景：深灰黑，不使用纯黑；
- 正文：柔和灰白；
- 代码块：比背景略亮；
- 分割线：低对比；
- 强调色：降低饱和度，避免刺眼。

## 5.3 字体与排版

### 正文

- 中文正文使用系统默认字体；
- 英文和代码使用等宽字体；
- 正文字号默认 16sp；
- 行高建议 1.55～1.7；
- 段落间距明显大于普通换行；
- 页面左右 padding 建议 20dp～24dp。

### 标题

- H1：大标题，强层级；
- H2：章节标题；
- H3：小节标题；
- H4-H6：弱化处理，不要造成过多视觉噪音。

### 代码块

- 使用独立背景；
- 圆角 10dp～14dp；
- 内边距 12dp～16dp；
- 支持横向滚动；
- 字号 13sp～14sp；
- 行距略紧凑。

# 6. 数据结构设计

## 6.1 最近阅读记录 DocumentEntity

用于 Room 本地数据库。

```kotlin
@Entity(tableName = "documents")
data class DocumentEntity(
    @PrimaryKey val id: String,
    val displayName: String,
    val uri: String,
    val mimeType: String?,
    val fileSize: Long?,
    val lastOpenedAt: Long,
    val createdAt: Long,
    val lastScrollIndex: Int,
    val lastScrollOffset: Int,
    val readingProgress: Float,
    val title: String?,
    val headingCount: Int,
    // —— 实现已扩展（以代码为准）——
    val documentType: String,          // MARKDOWN / PDF
    val pageCount: Int = 0,            // PDF 页数
    // PDF 视口会话恢复字段（阅读模式 / 页索引 / 页内锚点分数）……
)
```

### 字段说明

| 字段 | 说明 |
|---|---|
| id | 文件 URI 或 URI hash 生成的稳定 ID |
| displayName | 展示文件名 |
| uri | Android SAF 文件 URI |
| mimeType | 文件类型 |
| fileSize | 文件大小 |
| lastOpenedAt | 最近打开时间 |
| createdAt | 首次导入时间 |
| lastScrollIndex | LazyColumn 最后阅读位置 index |
| lastScrollOffset | 最后阅读位置 offset |
| readingProgress | 阅读进度，0～1 |
| title | 从 Markdown H1 提取的标题 |
| headingCount | 标题数量，用于判断是否显示目录入口 |

## 6.2 文档解析模型 MarkdownBlock

Markdown 文件解析后转换为块级结构，方便长文分块渲染。

```kotlin
sealed class MarkdownBlock {
    data class Heading(
        val level: Int,
        val text: String,
        val anchor: String
    ) : MarkdownBlock()

    data class Paragraph(
        val text: String
    ) : MarkdownBlock()

    data class Quote(
        val text: String
    ) : MarkdownBlock()

    data class CodeBlock(
        val language: String?,
        val code: String
    ) : MarkdownBlock()

    data class ListBlock(
        val ordered: Boolean,
        val items: List<String>
    ) : MarkdownBlock()

    object Divider : MarkdownBlock()
}
```

# 7. 技术方案建议

## 7.1 技术栈

| 类型 | 技术 |
|---|---|
| 语言 | Kotlin |
| UI | Jetpack Compose |
| 架构 | MVVM |
| 本地数据库 | Room |
| 轻量配置 | DataStore |
| 文件选择 | Android Storage Access Framework |
| 异步任务 | Kotlin Coroutines / Flow |
| 主题 | Material 3（Dynamic Color 增强） |
| 导航 | Navigation Compose |
| PDF 渲染 | Android `PdfRenderer` + 分块瓦片管线 |
| PDF 元数据/大纲 | Apache PDFBox (android) |
| 阅读 chrome 材质 | `backdrop` 液态玻璃（Reader chrome / Home 浮控共享配方） |

## 7.2 渲染策略

不要把整篇 Markdown 一次性塞进一个 WebView 或 TextView。

推荐策略：

1. 读取文件内容；
2. 后台线程解析 Markdown；
3. 转换成块级 `MarkdownBlock`；
4. 使用 Compose `LazyColumn` 分块渲染；
5. TOC 根据 Heading block 自动生成；
6. 保存 `LazyListState` 作为阅读位置。

这样更容易实现：

- 长文性能优化；
- 目录跳转；
- 阅读进度保存；
- 块级样式定制；
- 后续搜索和局部刷新。

# 8. 非功能性需求

## 8.1 性能要求

| 场景 | 要求 |
|---|---|
| App 冷启动 | 尽量控制在 1 秒左右进入主页 |
| 普通文档打开 | 1 秒内展示内容 |
| 超长文档打开 | 优先展示首屏，解析过程不可阻塞 UI |
| 滑动体验 | 无明显掉帧 |
| 数据库查询 | 最近阅读列表秒开 |
| 文件读取 | 不在主线程读取大文件 |

## 8.2 隐私要求

- 不申请网络权限；
- 不上传任何文件；
- 不接入统计 SDK；
- 不接入广告 SDK；
- 不读取用户未主动选择的文件；
- 删除历史记录时**永不删除用户源文件**（仅清理 App 自管的私有副本，且需无其他记录引用）。

## 8.3 兼容性要求

- 支持 Android 12 及以上；
- 适配深色模式；
- 适配横竖屏基础布局；

# 9. 验收标准（Markdown 阅读 · 原始 MVP 基线）

## 9.1 主页验收

- 首次打开显示空状态；
